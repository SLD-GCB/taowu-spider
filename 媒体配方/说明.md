# 媒体配方（音视频抓取策略）说明书

一个 `.json` 文件 = 一个网站的抓取策略。**改配方不改代码。**

## 两套目录：自带 与 用户

| | 目录 | 谁写 | 程序升级时 |
|---|---|---|---|
| **自带** | `媒体配方/`（就是本目录） | 随包发，别在这里写自己的配方 | **会被整体覆盖** |
| **用户** | `用户配方/` | 你自己写／导入的 | **原样保留** |

配方由 `media_recipe.py` 读取并注册进解析器注册表，程序每次解析页面时会加载。
注册顺序是**自带全部先、用户全部后**，同 `host_suffix` **后注册者赢** —— 所以你在
`用户配方/` 放一份 `bilibili.json`，就能盖掉自带的 B 站配方，而升级不会动它。

> **不要把自己的配方放进 `媒体配方/`**：那是自带目录，升级时会被整个替换掉。

## 界面入口

**管理入口只有一个：主界面的「配置管理」白色按钮**（或「通用媒体下载」弹窗里的
「媒体配方」按钮，打开的是同一个组件）。点开 → 「媒体配方」页 → **导入… / 停用·启用 /
查看内容 / 打开目录 / 重新扫描**都在那儿。⚠ 2026-09-11 起配方行上的「停用」「导入配方」
按钮**已撤掉**，同一个入口不再有第二份。

「通用媒体下载」弹窗里留下的那一行只负责**选**：

```
配方： [自动（按网址匹配，默认）  ▾]
```

- **自动** = 按网址域名挑配方（默认，平时就用这个）。
- **选中某一份** = 只用它解析，**解析不出也不退回静态/浏览器兜底**。这是用来确认
  "我这份配方到底通不通"的；能出候选才说明配方真的生效了。
- 已**停用**的配方仍然列在下拉里（灰掉、后面缀「（已停用）」）—— 不留在那儿你就没法把它
  选回来再启用；选中它不会生效，配置管理里重新启用即可。
- **导入** = 选一份写好的 json，**先校验再复制**进 `用户配方/`。写错了会被拒绝
  并指出具体哪一行（例如 `配方.emit[0].when 用了不认识的算子 op='non_empty'`），
  不会导进来一张永远不生效的哑配方。
- **停用/启用对自带配方也有效**，而且升级后仍记得（状态存在 `runtime/media_recipe_state.json`，
  不写回 json）。

配置管理里状态列写 **（校验未通过）** 的项说明那份 json 有错、当前不生效；点「查看内容」
直接看原文。改好存盘即自动重载，不用重启。

## 基本约定

| | |
|---|---|
| 放哪里 | 自己写的放 `用户配方/`；随包的三个在 `媒体配方/` |
| 文件名 | `随便起.json`。**以 `_` 开头的会被忽略**，放模板和草稿不会被当成配方 |
| 怎么生效 | 存盘即生效（按修改时间自动重载），不用重启，不用重新打包 |
| 编码 | UTF-8（带 BOM 也行） |
| 注释 | 键名以 `_` 开头的会被引擎忽略，可以拿来说明白（JSON 本身不支持注释） |

随包的三个配方就是活样例，遇到问题先翻它们：
`bilibili.json`（自家播放 API + 分P）、`youtube.json`（多客户端阶梯 + 双形态择优）、
`douyin.json`（HTTP 死路 → 浏览器辅助）。

## 0. 先想清楚：这个站的地址从哪来

写配方之前只需回答一个问题：**播放地址是怎么被发现的？** 决定了走哪种写法。

| 站型 | 特征 | 怎么写 |
|---|---|---|
| **① 自家播放 API** | 页面 HTML 里有视频 id，调一个接口就返回带直链的 JSON | `identity` + `steps` + `emit`。最干净，纯 HTTP，最稳 |
| **② 接口要签名** | 接口存在，但参数带 `a_bogus`/`wbi`/`sign` 之类的签名 | **不要试图算签名**（红线）。改用 `browser_seam` 让真浏览器自己去调 |
| **③ SPA / 流在 Worker 里** | 页面是前端框架，播放地址藏在 JS 运行时、MSE、Web Worker 里 | `browser_seam`：开真浏览器，**旁观页面自己发出的请求**，从响应里捡直链 |

`browser_seam` 是兜底，不是首选：它要开 Chrome、慢十几秒、拿到的直链常常带时效。
能用 ① 就别用 ③。

## 1. 骨架

```json
{
  "schema_version": 1,
  "name": "mysite",
  "desc": "某个站，写给自己看的说明",

  "host_suffix": ["mysite.com"],
  "short_hosts": ["mst.cn"],
  "cookies": "jar",

  "identity": { "any_of": [ { "name": "vid", "pattern": "/video/(\\d+)" } ] },
  "steps":    [ ... ],
  "emit":     [ ... ]
}
```

| 顶层字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | | 目前恒为 `1`。写大了程序会拒绝并提示升级 |
| `name` | ✅ | 配方名，注册表里的身份证。**别和别的配方重名** |
| `desc` | | 备注，纯给自己看 |
| `enabled` | | `false` = 停用（保留文件但不注册）。临时关掉一个配方用这个，别删 |
| `order` | | 同后缀冲突时的注册次序，小者先，默认 100。用户配方靠"后注册赢"覆盖内置，一般不用写 |
| `host_suffix` | ✅ | 命中哪些域名，字符串或数组。**子域自动命中**（写 `mysite.com` 就同时管 `www.mysite.com`、`m.mysite.com`）；多后缀按最长匹配优先 |
| `short_hosts` | | 分享短链域名（如 `b23.tv`）。程序会先跟重定向拿到真实网址，再进配方 |
| `cookies` | | 这个站要不要 cookie：`none` / `session` / `jar` / `session+jar`，默认 `jar` |
| `session` | | 身份引导（见 §5）：UA、Referer、首次访问种 cookie |
| `identity` | | URL → 变量（见 §4） |
| `steps` | | HTTP 取数步骤（见 §6） |
| `emit` | | 变量 → 轨道（见 §7） |
| `browser_seam` | | 浏览器辅助缝（见 §8） |

`emit` 和 `browser_seam` **至少得有一个**，否则这个配方什么也产生不了。

## 2. 取值语法：配方里每个"值"位置能写什么

配方的本质是"**从接口 JSON 里把几个字段挑出来**"。凡是写"值"的地方（`set` 的值、
`track.url`、`sort` 的路径……）都支持下面这一套。**不用记全，先记 `{"path": ...}` 和字符串模板。**

### 2.1 字符串 = 模板

```json
"https://api.mysite.com/video/{vid}/play"
```

`{...}` 里是**路径**，从当前变量里取值填进去。整串只有一个占位符时**保留原类型**
（`"{dur}"` 得到数字而不是字符串 `"12"`）。

> **坑**：光秃秃的字符串**永远是模板**，不是路径。要取值必须写成 `{"path": "..."}`。
> 唯一例外是 `pick.path`、`match.path`、条件里的 `path` —— 这些键名叫 `path`，按约定就是路径。

### 2.2 路径语法

```
data.pages[0].cid        点分取键 + [n] 下标
dash.video[].baseUrl     [] 通配：取该层全部，得到列表
```
任一段没走到 → 该值视为"缺失"。通配只命中一个元素时会**退化成标量**而不是单元素列表
（所以判断列表的算子要能同时吃两种形状，见 §3.4）。

### 2.3 取值算子

| 写法 | 作用 |
|---|---|
| `{"path": "a.b", "default": "x"}` | 取路径，取不到用 `default`。**只允许 path+default 两个键**，多一个键就变成普通对象了 |
| `"前缀{path}后缀"` | 模板拼串 |
| `{"const": 值}` | 常量。想表达"空串"就得用 `{"const": ""}`（见 §2.5） |
| `{"pick": {...}}` | **选优**：从列表里挑一条，配方最常用的算子（见 §2.4） |
| `{"match": {"path": "mimeType", "pattern": "^video/(\\w+)", "group": 1, "default": "?"}}` | 正则**提取**一段。抽不到给 `default` |
| `{"int": ...}` / `{"float": ...}` / `{"str": ...}` | 类型转换。转不动给 0 / 0.0 / "" |
| `{"len": ...}` | 长度 |
| `{"bool": [条件]}` | 条件成立否 → true/false |
| `{"any": [a, b, c]}` | 第一个非空的值（跳过 null/""/0/[]/{}） |
| `{"not": ...}` | 逻辑非 |
| `{"size": ...}` | 字节数格式化成 `1.0MB` 这类可读串 |
| `{"ext_of": {"url": ..., "whitelist": [...], "default": "mp4"}}` | 从 URL 猜扩展名 |
| `{"join": [a, b], "sep": "｜"}` | 拼串，空值自动跳过 |
| `{"div"/"mul"/"add"/"sub": [a, b]}` | 四则运算（`div` 除零给 0） |
| `{"min"/"max": [a, b]}` | 取小/取大 |
| `{"list": [a, b]}` | 求值成数组（POST body 的数组参数） |
| `[{"when": [条件], "value": 值}, ...]` | **规则表**：第一个条件成立的胜出。这就是配方里的 if/else |
| `[值, 值, ...]` | 字面量数组，逐元素求值 |
| `{普通对象}` | 逐值递归求值 —— POST body / 字面量对象走这条 |

**规则表 vs 字面量数组**靠形状自动区分：每个元素都是带 `value`/`when` 的字典 → 按规则表。
所以字面量数组里别写恰好长那样的元素。

### 2.4 `pick` —— 从一堆候选里挑最好的一条

几乎每个站都要做这件事：接口返回十条不同清晰度的流，得挑一条。这就是它。

```json
{"pick": {
  "path": "data.quality_list",
  "where":  [ {"path": "codec", "op": "ne", "value": "h265"} ],
  "sort":   [ {"mul": ["width", "height"]}, {"path": "bitrate"} ],
  "require_len": 1,
  "take": 0
}}
```

| 键 | 说明 |
|---|---|
| `path` / `list` | 候选列表从哪来（`list` 可写任意取值表达式） |
| `where` | 过滤条件（AND）。条件里的路径是**相对候选元素**的短路径：写 `"codec"` 而不是 `"data.quality_list[].codec"` |
| `sort` | **有序**排序规则，靠前的键优先 |
| `require_len` | 过滤后不足这么多条 → 整个 `pick` 返回 null。用来表达"视频和音频都得有才算一对" |
| `take` | 取第几个（默认 0 = 最好）。越界返回 null |

`sort` 里每条规则的写法：`{"path": "字段", "order": "desc"}`（默认 desc），或
`{"mul": ["width","height"]}`（字段相乘当排序键），或 `{"prefer_re": "avc1", "path": "codec"}`
（匹配的正则排前面）。

### 2.5 空值会被丢掉 —— 一个 body 服务所有档位

普通对象（字面量对象）里，**求值结果为空串的键会整个消失**。这不是 bug，是刻意设计：

```json
"json": { "videoId": "{vid}", "androidSdkVersion": "{cli.sdk}" }
```
`youtube.json` 用同一份 body 模板服务 ANDROID / IOS / WEB 三档客户端 —— WEB 那档没有
`cli.sdk`，渲染成空串后这个键自动消失，不用为每档抄一份 body。

反过来说：**真的想要一个空串值，必须写 `{"const": ""}`。**

## 3. 条件（`when` / `expect` / `where` / `validate`）

条件是一个**只有比较、没有脚本**的微表达式。列表 = AND；空列表 = 恒真（"无条件即放行"）。

```json
{"path": "playabilityStatus.status", "op": "eq", "value": "OK"}
{"any": [ {"path": "a", "op": "nonempty"}, {"path": "b", "op": "nonempty"} ]}
{"all": [ ... ]}
{"not": {"path": "x", "op": "exists"}}
```

`op` 省略时：有 `value` 就当 `eq`，没有就当 `exists`。

### 3.4 算子表

**比较**：`eq` `ne` `gt` `ge` `lt` `le` `in` `nin` `contains` `contains_i` `re`
`startswith` `endswith`（`contains_i` = 忽略大小写的 contains）

**长度**：`len_eq` `len_ne` `len_gt` `len_ge` `len_lt` `len_le`

**存在性**：`exists`（路径走到了，哪怕是 null）`nonempty` / `truthy`（有内容）
`empty` / `falsy`（没内容）

**列表**（路径带 `[]` 通配时值是列表）：
- `any_re` / `all_re` —— 至少一个 / 每一个元素匹配正则
- `any_eq` / `all_eq` —— 至少一个 / 每一个元素等于某值

> 例：`{"path": "formats[].mimeType", "op": "any_re", "value": "^video/mp4"}`
> = "这些格式里至少有一个是 mp4 视频"。

**算子拼错会被当场拒绝**（否则它只会静默判否，表现为"这个分支永远不命中"，极难查）。

### 3.5 `where` 里的路径是短路径

`where` / 条件在 `pick` 里时，路径相对**候选元素**：
```json
{"pick": {"path": "list", "where": [{"path": "mimeType", "op": "contains", "value": "audio"}]}}
```
同时外层变量**仍然可用**（值里的 `{video_id}` 能取到）。短路径优先命中。

## 4. `identity` —— 从网址里取变量

用户贴进来的网址形式五花八门（分享链接、短链、App 内链、带一堆跟踪参数），
先归一成变量，后面才好拼 API。

```json
"identity": {
  "any_of": [
    {"name": "aweme_id", "pattern": "/share/video/(\\d+)"},
    {"name": "aweme_id", "pattern": "/video/(\\d+)"},
    {"name": "aweme_id", "pattern": "[?&]modal_id=(\\d+)"}
  ],
  "query": [
    {"name": "p", "param": "p", "type": "int", "default": 1, "min": 1}
  ]
}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 捕获组存进哪个变量。**缺了这条规则永远不命中**（校验器会拦） |
| `pattern` | ✅ | 正则。**捕获组 1** 就是值；没有捕获组时用整个匹配 |
| `type` | | 写 `"int"` 则转成整数 |
| `from` | | 只是写给人看的出处备注，引擎不读 |

`any_of` / `all_of` 里可以放**多条规则**：
- 放一串规则 = 每条都是一个**备选**，`any_of` 取第一个命中的（上例就是三种网址形式）。
- 放一个**嵌套数组** = 这一组里的规则必须**全部**命中。

`query` 表从网址的查询串里取参数：

| 键 | 说明 |
|---|---|
| `name` | 存成什么变量（不写就用 `param`） |
| `param` | 取哪个查询参数 |
| `type` | `"int"` 转整数；配合 `min`/`max` 夹范围 |
| `default` | 参数不在网址里时用这个 |

取到的变量全局可见，`steps`/`emit` 里直接 `{aweme_id}` 用。
**一条规则都没命中 → 这个配方就不接这个网址**（返回空，交给别的配方/兜底）。

### 4.1 URL 里带中文（或空格）的变量 —— **原样传，别解码**

有些站把搜索词之类的文本写进网址（`…search.html#searchKeyWord=%E5%91%A8%E6%9D%B0%E4%BC%A6`）。
浏览器写进去时**已经 percent-encode 过**，你正则捕获到的是那串 `%E5%91%A8…`。

**直接把它拼进下一跳的 URL 就是对的**，什么都不用做：

```
正则捕获 → "%E5%91%A8%E6%9D%B0%E4%BC%A6"
拼出来   → …/search/song?keyword=%E5%91%A8%E6%9D%B0%E4%BC%A6     ← 服务器解码后 = 周杰伦 ✅
```

因为程序发请求时**不会把 `%` 再编一次**（`%` 属于安全字符）。反过来，你手打的网址里要是
**没编码**的中文，程序会替你编一次 —— 两条路殊途同归。

**反例（别这么写）**：先解码再拼。那样程序会补编一次，服务器收到的是字面
`%E5%91%A8…`（`%25E5%91%A8…`），**搜出来 0 条**，而且不报错 —— 症状就是"这个站搜不到东西"。
引擎**没有**解码/编码算子，也不打算加：原样传已经对了。

## 5. `session` —— 身份引导

有些站匿名访问会被降级（只给低清、或直接拒绝），得先摆出正常浏览器身份。

```json
"session": {
  "user_agent": "Mozilla/5.0 (...) Chrome/124.0.0.0 Safari/537.36",
  "referer": "https://www.mysite.com/",
  "headers": {"Accept-Language": "zh-CN,zh;q=0.9"},
  "bootstrap": {
    "url": "https://www.mysite.com/",
    "method": "GET",
    "cookies_from": "response",
    "cookie_domain": ".mysite.com",
    "expect": [ {"path": "code", "op": "eq", "value": 0} ]
  }
}
```

**引导只在这个配方真要发请求时才跑一次**，不带 `bootstrap` 的配方零额外往返。

`bootstrap` 的 `cookies_from`：`response`（从响应 Set-Cookie 收）或 `页面`（从 HTML 里正则抠）。
`cookie_domain` 建议写 `.域名` 形式。

## 6. `steps` —— HTTP 取数

一步 = 一次请求，结果按 `as` 存进变量。

```json
"steps": [{
  "name": "取播放信息",
  "method": "POST",
  "url": "https://api.mysite.com/player",
  "referer": "https://www.mysite.com/video/{vid}",
  "headers": {"Content-Type": "application/json"},
  "json": {"vid": "{vid}", "quality": "{qn}"},
  "cookies": "jar",
  "required": true,
  "as": "play",
  "expect": [ {"path": "code", "op": "eq", "value": 0} ],
  "ladder": {"var": "qn", "values": [120, 80, 64]}
}]
```

| 键 | 说明 |
|---|---|
| `url` / `alt_url` | 主地址 / 备用地址。**写一个字符串或一个数组都行**；数组里逐个看"占位符齐不齐"，取第一个齐的那条（`bilibili.json` 用 bvid 与 aid 两条，`kugou.json` 用老/新两种歌页形态） |
| `referer` / `alt_referer` | 同上，取第一个能渲染出非空的 |
| `parse` | **从非 JSON 响应里抽数据**（页面 HTML / JS 里的内联 JSON），见 6.2 |
| `method` | 默认 GET |
| `json` / `body` | 请求体。`json` = JSON body，`body` = 原样字符串 |
| `headers` | 渲染后**为空串的头会被丢弃**（"这档不要 UA"就写空串，别塞空值顶掉会话默认） |
| `cookies` | 覆盖配方级设置：`none`/`session`/`jar`/`session+jar` |
| `as` | 结果存进哪个变量。不写就用步骤名 |
| `required` | `true` = 这步失败则整个配方放弃（默认 false，失败就跳过） |
| `when` | 条件不成立则跳过这步 |
| `expect` | 对响应的断言。**不成立则视为这步失败**（走 `ladder` 下一档 / 按 `required` 处理） |
| `timeout` | 秒 |
| `ladder` | **阶梯重试**：见下 |

### 6.1 `ladder` —— 换着参数试到成功

很多站要按"客户端"或"清晰度"试好几轮，前一轮被拒就换下一档。

```json
"ladder": {
  "var": "cli",
  "values": [
    {"clientName": "ANDROID", "clientVersion": "20.10.38", "ua": "..."},
    {"clientName": "IOS",     "clientVersion": "20.10.4",  "ua": "..."}
  ]
}
```

`var` 是每轮写进变量的名字，`values` 按序试。值**可以是对象**（`youtube.json` 就是拿它一次
换掉 body 里嵌的整套客户端身份），配合 §2.5 的"空值键消失"，一份 body 模板吃遍所有档。

**命中即止**：某一档的 `expect` 全过就停，不再试后面的。所有档都失败 → 这一步失败。

### 6.2 `parse` —— 从页面 HTML 里抽内联数据

`url` 默认按 JSON 解析响应。但很多站（尤其 SSR 的页面）**把初始数据直接嵌在页面里**：

```html
<script>
  var dataFromSmarty = [{"hash":"B6A0…","song_name":"汪苏泷"}],//当前页面的信息
      playType = "search_single";
</script>
```

这种情况配 `parse`，先取回页面原文，再用正则把那段 JSON 抠出来：

```json
{
  "url": "https://www.kugou.com/mixsong/{slug}.html",
  "parse": {"re": "dataFromSmarty\\s*=\\s*(\\[.*?\\])", "json": true, "index": 0},
  "as": "h",
  "expect": [ {"path": "h.hash", "op": "nonempty"} ]
}
```

| 键 | 说明 |
|---|---|
| `re` | **必填**，正则。有捕获组取第 1 组，没有则取整个匹配 |
| `json` | 默认 `true`：把抠出来的文本当 JSON 解析；`false` 则原样给字符串 |
| `index` | 结果是列表时取第几个（上面那段就是单元素数组，所以写 0） |
| `unescape` | 默认 `false`：抠出来的值要不要做 **HTML 实体解码**（见下） |
| `from` | 只是写给人看的出处备注，程序不读 |

**`unescape`（2026-09-10 新增）：从 HTML 里抠文字时开，抠 JSON 时别开。**

- **什么时候开**：抓的是 HTML 里的**文字**（`<title>`、属性值）。酷我歌页标题真机长这样
  `<title>爆了(Live)_古巨基&amp;黄子弘凡_单曲在线试听_酷我音乐</title>` —— 不开就会打印成
  `古巨基&amp;黄子弘凡`，还顶进文件名。
- **什么时候别开**：抠的是**内联 JSON**（`6.2` 上面那个 `dataFromSmarty`）。那里的 `&` 是字面量，
  不是转义文本，解了反而是错的。所以**默认关**——你不写，行为就跟以前一模一样。
- **它不会把签名 URL 解坏**：只认 `&amp; &lt; &gt; &quot; &apos; &nbsp;` 六个名实体（**且必须有分号**）
  和 `&#数字;` `&#x十六进制;`。`&times` 这种**没分号的**名实体一个字都不碰 —— 否则
  `&timestamp=…` 会被解成 `×stamp=…`，整条地址作废（项目早年在 `_safe_unescape` 栽过）。
- `json: true` 时**内层的字符串也会解**（`{"a": ["x&amp;y"]}` → `x&y`），不会出现"写在内层悄悄不生效"。
- 写 `"true"` / `1` 这类**载入期直接报错**，不靠真值判断蒙。

几条纪律：

- **只支持 GET**。写在 POST 步骤上载入期就会报错（POST 的响应不走这条抽取）。
- **抽不出来 = 这步失败**：跟请求失败同路，走 `ladder` 下一档 / 按 `required` 处理，
  **绝不会把半截文本当数据往下传**。
- **正则别在 `]` 后面加 `\s*;`**：上面那段页面在数组后面跟的是 `,]//注释`，不是分号，
  加上分号的正则会一路吃到后面另一个 `];`（酷狗真机实测吞进 21KB），JSON 解析必然失败。
  要的是非贪婪的 `\[.*?\]`。
- 页面对 UA 挑剔的站，记得在 `session` 里给 `user_agent`——酷狗就是**不带 UA 直接 403**
  （老式 URL 没事，新式 `/mixsong/` 会静默 0 轨）。
- **别指望 `required` 救"变量名写错"**：`url` 里的 `{变量}` 渲染不出来时（拼错名、或这条 URL
  形态下压根没这个变量），这步是**跳过**——跳过**不算失败**，`required: true` 也拦不住，
  只在日志里留一句「步骤 X 跳过：URL 模板变量不全」（不翻日志就像静默失效）。同一份配方吃
  多种 URL 形态时，**给专属步骤写 `when`** 显式跳过，别让它靠"渲染不出来"兜底。

## 7. `emit` —— 变量 → 轨道

一条 emit 规则 = "在什么条件下，产出什么轨道"。

```json
"emit": [{
  "name": "主形态",
  "when": [ {"path": "play.code", "op": "eq", "value": 0} ],
  "set": {
    "u":      {"pick": {"path": "play.data.list", "sort": [{"mul": ["width","height"]}]}},
    "url":    {"path": "u.url"},
    "title":  {"join": ["{title}", "{whs}"], "sep": "｜"},
    "dur":    {"float": {"path": "u.duration"}}
  },
  "produce": [
    {"when": [{"path": "url", "op": "nonempty"}],
     "track": {
       "media_class": "video",
       "kind": "direct",
       "url": "{url}",
       "ext": "mp4",
       "title_hint": "{title}",
       "duration_s": "{dur}"
     }}
  ]
}]
```

| 键 | 说明 |
|---|---|
| `when` | 不成立就整条跳过 |
| `set` | 算一批中间变量，供 `steps`/`produce` 用。`steps` 存在时 `set` 会跑两遍（步骤前算 URL，步骤后刷新引用步骤结果的绑定） |
| `steps` | 这条规则自己的取数步骤（比如分P要逐集再请求一次） |
| `produce` | 产出规则列表，见下 |
| `track` | 直接产出一条轨道（没有 `produce` 时的简写） |
| `loop` | 分集展开：见 §7.2 |

### 7.1 `produce` —— 多形态择优

一个视频常有多种拿法（分轨 DASH / 渐进混流 / 分片 HLS）。挨个试，能出就出：

| 键 | 说明 |
|---|---|
| `when` | 条件 |
| `set` | 这条产出规则自己的中间变量 |
| `track` | 轨道声明 |
| `stop` | **命中即停**：这条出了轨就不再试后面的。用于**互斥形态** —— 分轨拿到了就别再退渐进，否则同一个视频会出两条轨。默认不写 = 继续试 |

`track` 字段：

| 字段 | 说明 |
|---|---|
| `url` | ✅ **唯一必须的**。渲染后为空 → 这条不出轨（于是"没这个地址"用条件表达很自然） |
| `media_class` | `video` / `audio`。**留空由程序按扩展名猜**（判不出来时用调用方的音/视频上下文兜底） |
| `kind` | `direct`（直链，默认）/ `hls` 或 `m3u8`（HLS 清单）/ `dash` 或 `mpd`（DASH 清单）。**只认这几个词，写别的会当场被拒绝** |
| `ext` | 扩展名，不给就按 URL 猜 |
| `title_hint` | 保存时的文件名提示 |
| `duration_s` | 时长（秒） |
| `note` | 显示在界面上的备注。用 `{"join": [...]}` 拼 |
| `cookies` | 下载这个文件要带的 cookie（覆盖配方级） |
| `ephemeral` | `true` = **时效直链**（带时间戳签名、可能过期）。界面上会打角标提醒尽快下 |
| `parts` | 需要合成的分轨：`[{"media_class":"video","url":"...","ext":"mp4"}, {"media_class":"audio",...}]`。视频轨+音频轨分开的 DASH 就这样表达，程序会调 ffmpeg 合成 |
| `drm` | 只写**标识**（让界面提示"这是加密流，已跳过"）。**配方不能解密，红线** |

### 7.2 `loop` —— 分集 / 分P

```json
"loop": {
  "path": "view.data.pages",
  "as": "page",
  "index_as": "pnum",
  "episode_param": "p",
  "max": 200,
  "pause": 1.0,
  "fallback": [ {"cid": "{cid}"} ]
}
```
对 `path` 取到的每一项跑一遍这条 emit 规则（`as` 是当前项的变量名，`index_as` 是序号）。
`episode_param` 会生成 `{page.episode_url}` 形式的带集号地址。`fallback`：列表取不到时用的
字面量兜底（如接口没回分P列表，就用单集信息凑一条）。

**`pause`（2026-09-10 新增）：每两项之间等的秒数**，不写 = 不等。
给「**逐项去问接口**」的配方当刹车用 —— 有些站按 IP 限速，打太密就返
`200 + 空数据`（不报错、也不给 4xx），症状看起来像"这站挂了"或"这些都付费"。
**只在项与项之间等**：第一项之前、最后一项之后都不等（10 项 = 等 9 次）。
配套的 `loop.steps` 就是在每项里发请求 —— 一次 `loop` 里有 N 项，就是 N 次请求，
`max` 是这 N 的上限。典型写法见随包的 `kugou.json`「搜索结果：逐首问播放信息」。

### 7.3 纯音频站怎么写

播客 / 电台 / 有声书 / 音乐站的 `track`，只有三点和视频不一样。

**1. `media_class` 写 `audio`，或者留空 —— 两种都对。**

- **留空** → 程序按 URL 扩展名猜（`.mp3` / `.m4a` / `.aac` / `.ogg` / `.flac` 都认得）。猜不出来时，
  如果调用方本来就在要音频（「抓取音频流」弹窗就是这样），就归到音频。
- **显式写 `audio`** → 程序照办，不再猜。

> **建议显式写。** 音频落 `output/audio`、视频落 `output/video`，走的是**两套完全不同的下载栈**。
> 留空能猜对是运气（地址正好带扩展名）；地址如果是 `...?id=123` 这种无扩展名接口，只有显式写才稳。

**2. `kind` 决定"这是不是一个播放清单"** —— 音频站最常见的三种形态：

| 你手上那个地址 | 写什么 | 程序会做什么 |
|---|---|---|
| `.mp3` / `.m4a` 直链 | `"kind": "direct"`（默认） | 直接下载 |
| `.m3u8`（HLS 清单） | `"kind": "hls"`（= `m3u8`） | 拉清单 → 逐分片下载 → ffmpeg 合成 |
| `.mpd`（DASH 清单） | `"kind": "dash"`（= `mpd`） | 同上 |

**写错的后果很实在**：该写 `hls` 却写成 `direct`（或反过来），程序会把那份 `.m3u8`
**文本本身**当成一个音频文件下回来 —— 你得到一个几百 KB、播不出来的"歌"。所以**别靠猜，看地址后缀**。

**3. 清单类的东西 `ext` 不用给。** `kind` 是 `hls`/`dash` 时产物容器由程序决定；`ext` 只在 `direct` 时起作用。

一个最小的纯音频配方（HLS 优先、退回直链）：

```json
{
  "schema_version": 1,
  "name": "某某电台",
  "host_suffix": ["example.fm"],
  "cookies": "none",

  "identity": { "any_of": [ {"name": "sid", "pattern": "/sound/(\\d+)"} ] },

  "steps": [{
    "name": "取播放信息",
    "url": "https://api.example.fm/sound/{sid}",
    "referer": "https://www.example.fm/sound/player?id={sid}",
    "as": "play",
    "required": true
  }],

  "emit": [{
    "produce": [
      {"name": "优先清单版",
       "when": [ {"path": "play.data.hls_url", "op": "nonempty"} ],
       "track": { "media_class": "audio", "kind": "hls",
                  "url": {"path": "play.data.hls_url"},
                  "title_hint": {"path": "play.data.title"} },
       "stop": true},

      {"name": "退回直链",
       "when": [ {"path": "play.data.mp3_url", "op": "nonempty"} ],
       "track": { "media_class": "audio", "kind": "direct",
                  "url": {"path": "play.data.mp3_url"}, "ext": "mp3",
                  "title_hint": {"path": "play.data.title"} }}
    ]
  }]
}
```

连载 / 有声书这种一个页面挂很多集的，在 `emit` 外面套一个 `loop`，见 §7.2。

> ⚠️ **加密的音频流不要写配方 —— 写了也出不来。**
> 拿浏览器 F12 → Network → 打开那份 `.m3u8`，只要看到下面任何一条，这就是商业 DRM，直接弃站：
>
> - `#EXT-X-KEY:METHOD=SAMPLE-AES`
> - `KEYFORMAT="com.apple.streamingkeydelivery"` 或 `skd://`（FairPlay）
> - `urn:uuid:edef8ba9-79d6-4ace-a3c8-27dcd51d21ed`（Widevine）
> - 分片地址路径里带 `/drm/`
>
> 这是 §10 的红线，不是"暂时没做"。

## 8. `browser_seam` —— 浏览器辅助缝（兜底手段）

**HTTP 走不通时用**：接口要签名、地址在 JS 里、流在 Worker 里。做法是开一个真 Chrome 打开页面，
**旁观页面自己发出的请求与响应**，从它自己拉到的 JSON 里捡直链。

> **只旁观，不代它构造请求。** 程序绝不会拿已知参数去替页面调接口 —— 这条是红线，写在代码里。

```json
"browser_seam": {
  "name": "mysite浏览器辅助",
  "url": "https://www.mysite.com/video/{vid}",
  "wait_sec": 24,
  "watch": {
    "path_contains": ["/api/detail/"],
    "url_contains": ["{vid}"],
    "json_require": [ {"path": "data.playurl", "op": "nonempty"} ],
    "validate":     [ {"path": "data.id", "op": "eq", "value": "{vid}"} ],
    "as": "detail",
    "max_bytes": 4194304
  },
  "emit": [ ... ]
}
```

| 键 | 说明 |
|---|---|
| `url` | 打开哪个页面（用 `{变量}` 拼） |
| `wait_sec` | 最多等多久 |
| `watch.path_contains` | 只认 URL 路径里含这些片段的响应（**这个站的接口长什么样，是你写配方时唯一必须现场看的东西**） |
| `watch.url_contains` | 再要求 URL 里含这些串（常用来保证"是这一条的详情，不是推荐位的"） |
| `watch.json_require` | 响应体必须满足的条件，否则这条响应不算数 |
| `watch.validate` | **拿到之后**再核对一遍，防串号（"我要的是 12345，回来的是别的视频"） |
| `watch.as` | 存进哪个变量（默认 `detail`） |
| `watch.max_bytes` | 超过这个大小的响应不读（默认 4MB） |
| `emit` | 拿到之后怎么产出轨道，格式与 §7 完全一致 |

`wait_sec` 给宽一点：页面常常要等用户手势才开始加载播放器，程序会自动做几轮触发（模拟点击播放）。

**这一节拿到的直链通常带时效 token**，记得在 `track` 里写 `"ephemeral": true`。

## 9. 校验与排错

**写完先校验。** 在程序目录下执行（改了配方名就换文件名）：

```bash
python -c "import media_recipe as m; s,e=m.load_recipe('媒体配方/mysite.json'); print(e or 'OK')"
```

`OK` = 合法。报错会指出**具体位置**，比如：

```
配方.emit[0].when[0] 用了不认识的算子 op='non_empty'（可用：eq/ne/.../len_le）
配方.browser_seam 含未知键 'desc'（允许：emit/enabled/identity/name/url/wait_sec/watch）
配方.emit[0].produce[0] 含被禁键 'sign' —— 配置不支持签名/解密/验证码/脚本一类能力（红线）
```

程序运行时也会把不合法配方记进日志（`媒体配方未注册 xxx：...`），**不合法就不注册、不报错崩溃**，
所以"某个站突然解析不出"时，第一步永远是去看校验输出。

排查套路：

1. **校验过不了** → 按报错改字面。
2. **校验过了但啥也没抓到** → 先看是"请求没发"还是"发了但没挑出来"：
   - `identity` 没匹配上 → 换个网址形式试试（分享链接和网页链接的 `re` 往往不一样）。
   - `steps` 的 `expect` 没过 → 把 `expect` 临时去掉，看看到底回了什么。
   - `pick` 挑空了 → 大概率是 `where` 写太严或路径写错，先把 `where`/`sort` 去掉试试。
3. **拿到的直链下载 403** → 多半是防盗链，补 `referer` 和 `cookies`。
4. **一条视频出了两条轨** → 两条 `produce` 都命中了，给优先的那条加 `"stop": true`。
5. **路径取不到值** → 记住光秃秃的字符串是**模板**不是路径，要写 `{"path": "..."}`。

## 10. 红线（这些写不进去）

配方是**数据**，不是代码。下面这些键名一旦出现在任何层级，校验器会直接拒绝并说明原因：

```
eval / exec / script / js / code / python / lambda / expr
sign / signature / a_bogus / wbi / nsig / n_sig / potoken / botguard
decrypt / decode / key / license / widevine / playready / fairplay / clearkey
captcha / verify_code
```

也就是：**不生成签名、不解密、不破验证码、不执行脚本。**

这不是能力不足，是刻意的边界：

- **商业 DRM（Widevine / PlayReady / FairPlay）绝不解密。** 遇到加密流，配方只能把它标出来
  （`drm` 字段）让界面跳过。
- **不生成签名。** 接口要求 `a_bogus`/`wbi` 一类签名时，**换思路**：用 `browser_seam` 让真浏览器
  自己去调（它本来就带签名），而不是在配方里把它算出来。
- **只旁观，不代劳。** `browser_seam` 只看页面自己发出的请求，绝不替页面构造请求 —— 哪怕
  参数完全已知。
- 不做全流捕获 / MSE 抓帧。

## 11. 速查：一个最小可用配方

```json
{
  "schema_version": 1,
  "name": "example",
  "desc": "最小样例：一个接口就返回直链的站",

  "host_suffix": ["example.com"],
  "cookies": "jar",

  "identity": { "any_of": [ {"name": "vid", "pattern": "/video/(\\d+)"} ] },

  "session": {
    "referer": "https://www.example.com/",
    "headers": {"Accept-Language": "zh-CN,zh;q=0.9"}
  },

  "steps": [{
    "name": "取播放信息",
    "url": "https://api.example.com/play?id={vid}",
    "referer": "https://www.example.com/video/{vid}",
    "as": "play",
    "expect": [ {"path": "code", "op": "eq", "value": 0} ]
  }],

  "emit": [{
    "when": [ {"path": "play.data.url", "op": "nonempty"} ],
    "set": {
      "whs": {"join": [{"path": "play.data.width"}, {"path": "play.data.height"}], "sep": "x"}
    },
    "track": {
      "media_class": "video",
      "kind": "direct",
      "url": {"path": "play.data.url"},
      "ext": {"ext_of": {"url": {"path": "play.data.url"}, "default": "mp4"}},
      "title_hint": {"path": "play.data.title"},
      "duration_s": {"path": "play.data.duration"},
      "note": {"join": ["{whs}"], "sep": ""}
    }
  }]
}
```

改成你的站，存进本目录，就生效了。
