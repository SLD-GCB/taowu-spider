# 用户字段配置说明（文字抽取引擎 + 数据表模板）

设好这份东西，你**只改 JSON、不写任何代码**，就能给文字抽取引擎加自己的字段匹配规则，
以及加自己的**数据表模板**（建表 + 字段匹配一套带走）。

**唯一的管理入口**是主界面白色按钮区的 **「配置管理」**。点开是三个页签：

| 页签 | 管什么 | 文件放哪 |
|---|---|---|
| 媒体配方 | 音视频站点的抓取策略（另一套，见 `媒体配方/说明.md`） | `用户配方/` |
| 数据表模板·字段配置 | **建表模板 + 字段匹配配置**（一份文件同时是这两样） | `用户字段配置/` |
| 字段规则片段 | 补几条 / 覆盖几条规则库的规则（导入即自动生效） | `用户字段配置/` |

每一页都是同一套操作：**导入… / 停用·启用 / 查看内容 / 打开目录 / 重新扫描**。
音视频弹窗里的「媒体配方」按钮打开的也是这个组件 —— 全部配置就这一处能改。

---

## 一、文件放哪儿

| 目录 | 谁的地盘 | 升级时 |
|---|---|---|
| `数据表模板/`、`字段规则/`、`媒体配方/` | 自带（随软件来） | **会被覆盖** —— 别往里写东西 |
| `用户字段配置/` | **你的**（导入按钮写这里） | **不动**，升级不会碰 |
| `用户配方/` | **你的**（媒体配方写这里） | **不动**，升级不会碰 |

同名时**用户那份赢**（后加载的覆盖先加载的）。自带与用户是**两份独立的配置，分开管理** ——
停用你那份，自带的同名配置会立刻回来。

配置管理里「查看内容」直接显示原文，「打开目录」会打开你自己的目录。**改完 JSON 回到配置管理
点一下「重新扫描」，再看一眼状态列**（哪份生效了、哪份写坏了、坏在哪一行）。

## 二、两种形状（按形状自动认，没有类型字段）

### 形状 1：字段配置 —— 一套完整的字段匹配

```json
{
  "id": "my_shop",
  "name": "我的商品页",
  "engine": "schema_v2",
  "columns": [
    {"name": "商品名", "type": "TEXT", "clean": "text",
     "synonyms": ["标题", "商品标题", "product"]},
    {"name": "价格", "type": "REAL",
     "re": ["￥(\\d+\\.?\\d*)\\s*元", "售价[：:]\\s*(\\d+\\.?\\d*)"]},
    {"name": "发货地", "type": "TEXT", "rule": "发货地_通用"}
  ]
}
```

- `name` **必填**（下拉框里显示的就是它）。
- 一列的匹配按这个顺序试：**列名/同义词查表 → `clean` 表单兜底 → 列内 `re` → `clean` 兜底**。
- `rule` 用来引用规则库里的规则（见形状 2）；`re` 是直接写在这一列上的正则。

### 形状 2：规则片段 —— 补几条/覆盖几条规则库的规则（**不用选，导入即自动生效**）

```json
{
  "_说明": "我自己补的几条",
  "发货地_通用": {
    "synonyms": ["发货地", "发货城市", "始发地"],
    "clean": "text",
    "re": ["发货地[：:]\\s*([\\u4e00-\\u9fa5]{2,10})"]
  }
}
```

- 顶层直接就是 `{规则名: 规则}`。规则名在**全库唯一**；跟自带规则同名 = **覆盖自带那条**。
- `_` 开头的键是注释，引擎会跳过（`_说明` 就是干这个的）。

## 三、建自己的数据表模板

**一份 JSON 同时是两样东西**，不是两种文件：

- 它是**数据表模板** —— `name` 是建出来的表名，`columns[].type` 是列类型；
- 它也是**字段匹配配置** —— `columns[].synonyms / clean / re / rule` 是抽取规则。

所以主界面上那两个下拉列的是**同一批 JSON 的两种视图**：

```
模板：     [▼ — 手动填表（不建模板表）— ]   ← 选一个 → 建同名表 + 把表名填进「表」输入框
抓取规则： [▼ 招聘信息（默认）        ]   ← 选一个 → 绑成抽取用的字段匹配规则
```

**能不能建表，看 `engine`**：

- 写 `engine: "schema_v2"` → 会出现在「模板：」下拉里，选中即建表；
- 不写、或写了别的值 → 它只是字段匹配配置，**导入时会直接拒绝**并提示你
  「这份 JSON 的 engine 是「(没写)」，不是 schema_v2」；
- ⚠ 两个下拉是**各管各的**（这是故意的，不是 bug）：选了 A 模板、规则那头绑着 B 配置 →
  抽取按 B 的列走、写进 B 同名的那张表，A 只起到建表作用。真出现这种不一致时日志会点名提醒你。

抄写用骨架见 `数据表模板/_模板-数据表.json`（带 `_` 前缀的文件不会生效，放心放在那儿）。

### 表名 / 列名 / 类型的硬规则（导入时逐条查，不通过就拒绝，不会落盘）

| 项 | 规则 |
|---|---|
| 表名（`name`） | 非空、≤64 字符；不能含反引号 `` ` ``、分号 `;`、换行、`\0` |
| 列名（`columns[].name`） | 同上；**不能用 `id`**（建表语句自己会写 `id` 主键，会撞成 duplicate column name）；同一份里不能重名 |
| 列类型（`columns[].type`） | 只能是 `TEXT` / `INTEGER` / `REAL` / `BLOB`。写了别的 → **降级成 `TEXT`**（导入时报错提醒，建表时兜底） |
| 引用的规则（`rule`） | 规则名必须在规则库里存在（自带的 + 你导入的规则片段）。**先导规则片段，再导引用它的表模板** |

这几条不是摆设：列名和表名会被直接拼进 `CREATE TABLE`，用户能自由导入之后它就是一个入口，
所以导入期（`validate_field_config`）和建表期（`template_create_fields` / `create_custom_table`）
各查一遍 —— 就算你绕过导入、直接把文件拷进目录，建表那一步也拦得住。

## 四、写 JSON 时的硬规则（踩过的坑，逐条对照）

1. **字符串里不要出现半角双引号 `"`** —— 会直接把 JSON 写坏。要引号请用中文引号「」。
2. **`re` 一定写捕获组 `( )`**。引擎的取值规则是「取第 1 个捕获组，有值用值，**否则取整段匹配**」
   （`schema_engine.py:153`）。所以 `"￥(\\d+)"` 抽出 `128`，而 `"￥\\d+"` 抽出的是 `￥128`
   —— 不写组不算错，但拿到的东西通常不是你要的。
3. **正则里的反斜杠要写成两个**：JSON 里 `\d` 是非法转义，必须写 `\\d`。
4. **坏正则现在会被当场拦下**。以前引擎对编译不过的正则**静默跳过**（`_compile_re` 缓存成
   `False` 就再也不管了），症状是「这个字段永远抽不出值」而页面上没有任何提示。导入时会逐条试
   编译，错了直接拒绝并告诉你错在哪一条。
5. **`clean` 只能是这几个**：`title` / `money` / `datetime` / `phone` / `link` / `longtext` / `text`。
6. **引用了不存在的规则名会被拒**（拼错了、或者那份规则片段还没导入）。所以**先导规则片段，
   再导引用它的字段配置 / 表模板**。
7. 文件名不能以 `_` 开头（那是「别扫我」的约定），也不能是 `.json` 以外的东西。

## 五、几个必须知情的边界

- **规则不是在导入时就冻结的**。配置绑定时会再核一遍「引用的规则还在不在库里」，不在就写一条
  ⚠ 日志。所以：**先导配置、后停用规则片段**，配置是能绑上的，但那几列会静默抽不出值 ——
  日志里有提示，导入期拦不住这种先后顺序。
- **停用 ≠ 删除**。文件还在原地，随时能再启用；停用只是让引擎不读它。
- **停用的配置仍然留在两个下拉里**（灰掉、后面缀「（已停用）」）—— 这是故意的：不留在那儿，
  你就没法把它选回来再启用（2026-09-11 之前「模板：」下拉是把它直接摘掉的，改成现在这样）。
  选中一个已停用的配置不会建表/不会绑上，会写一条日志告诉你先去「配置管理」里重新启用。
- **同名「自带 + 用户」两份都列出来**，各带各的 `[自带]` / `[用户]` 前缀，**选哪份是哪份**
  （真实键存在下拉项里，不是靠显示文本查的）。停用你那份 → 自带的同名那份立刻回来。
- **自带目录不可写**：写进去的东西下次升级会被覆盖（`build.py` 对这些目录是 rmtree + copytree）。
  `用户字段配置/` 和 `用户配方/` 不在那份拷贝清单里，永远不会被升级清掉。
- 状态存在 `runtime/field_config_state.json`（媒体配方在 `runtime/media_recipe_state.json`）；
  这两个文件坏了会被当成「全部启用」，不会让你的配置集体消失。
